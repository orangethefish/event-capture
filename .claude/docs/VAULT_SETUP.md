# HashiCorp Vault Integration

How to manage Event Capture secrets with HashiCorp Vault instead of manually editing
`production.env` on the VM.

## Overview

The Vault integration:

1. Stores all secrets in Vault KV v2 under `secret/data/event-capture/<environment>/`
2. Uses AppRole authentication for machine-to-machine access
3. Generates `production.env` on the VM by fetching secrets at deploy time
4. Supports manual secret refresh without full redeployment

The layered env-file approach is preserved:
- `production.env` — now generated from Vault (secrets)
- `release.env` — unchanged, still generated by Jenkins (non-secrets)

## Prerequisites

- HashiCorp Vault server (self-hosted or HCP Vault)
- `jq` and `curl` on the deployment VM
- Vault CLI on your workstation for initial setup

## 1. Vault Server Setup

### Option A: HashiCorp Cloud Platform (recommended)

HCP Vault provides a managed Vault cluster with automatic unsealing, backups, and TLS.
Create a cluster at https://portal.cloud.hashicorp.com and note the public endpoint.

### Option B: Self-Hosted

Minimum production requirements:

```hcl
# /etc/vault.d/vault.hcl
storage "raft" {
  path    = "/opt/vault/data"
  node_id = "vault-1"
}

listener "tcp" {
  address       = "0.0.0.0:8200"
  tls_cert_file = "/opt/vault/tls/vault.crt"
  tls_key_file  = "/opt/vault/tls/vault.key"
}

api_addr     = "https://vault.internal.example.com:8200"
cluster_addr = "https://vault.internal.example.com:8201"

# Auto-unseal with cloud KMS (required for unattended restarts)
seal "awskms" {
  region     = "ap-southeast-1"
  kms_key_id = "alias/vault-unseal"
}
```

## 2. Enable KV Secrets Engine

```bash
export VAULT_ADDR=https://vault.example.com:8200
vault login  # Use root token or admin credentials

# Enable KV v2 at secret/ (may already exist)
vault secrets enable -path=secret kv-v2
```

## 3. Create Policy

```bash
vault policy write event-capture-deploy - <<'EOF'
# Read-only access to event-capture secrets
path "secret/data/event-capture/*" {
  capabilities = ["read"]
}

# List secrets (useful for debugging, optional)
path "secret/metadata/event-capture/*" {
  capabilities = ["list"]
}
EOF
```

## 4. Configure AppRole Authentication

```bash
# Enable AppRole auth method
vault auth enable approle

# Create the role
vault write auth/approle/role/event-capture-deploy \
    token_policies="event-capture-deploy" \
    token_ttl=1h \
    token_max_ttl=4h \
    secret_id_ttl=0 \
    secret_id_num_uses=0

# Get the Role ID (not sensitive, can be committed)
vault read -field=role_id auth/approle/role/event-capture-deploy/role-id

# Generate a Secret ID (sensitive, store on VM only)
vault write -f -field=secret_id auth/approle/role/event-capture-deploy/secret-id
```

## 5. Store Secrets in Vault

Organize secrets by concern:

```bash
# Database
vault kv put secret/event-capture/production/database \
    url="jdbc:postgresql://postgres:5432/event_capture" \
    username="event_capture" \
    password="$(openssl rand -base64 24)"

# Redis
vault kv put secret/event-capture/production/redis \
    host="redis" \
    port="6379"

# Object storage (R2)
vault kv put secret/event-capture/production/storage \
    provider="r2" \
    bucket="event-capture-prod" \
    account_id="db46304bb3273f0f4224a9d1a1cb3441" \
    endpoint="https://db46304bb3273f0f4224a9d1a1cb3441.r2.cloudflarestorage.com" \
    access_key="YOUR_R2_ACCESS_KEY" \
    secret_key="YOUR_R2_SECRET_KEY"

# SMTP
vault kv put secret/event-capture/production/smtp \
    host="smtp.gmail.com" \
    port="587" \
    username="your-email@gmail.com" \
    password="your-app-password" \
    from="Event Capture <noreply@example.com>"

# Auth secrets
vault kv put secret/event-capture/production/auth \
    abuse_key_secret="$(openssl rand -base64 32)" \
    share_token_active_key_id="prod-v1" \
    share_token_keyring="prod-v1=$(openssl rand -base64 32)" \
    turnstile_site_key="0x4AAAA..." \
    turnstile_secret="0x4AAAA..." \
    turnstile_expected_hostname="capture.orangethefish.id.vn" \
    google_client_id="" \
    google_client_secret="" \
    google_redirect_uri=""

# Application settings
vault kv put secret/event-capture/production/app \
    base_url="https://capture.orangethefish.id.vn" \
    frontend_origin="https://capture.orangethefish.id.vn" \
    trusted_proxy_cidrs="172.28.0.0/24"
```

## 6. Configure the VM

Create the Vault auth file on the deployment VM:

```bash
sudo mkdir -p /opt/event-capture/shared
sudo tee /opt/event-capture/shared/vault-auth > /dev/null <<'EOF'
VAULT_ADDR=https://vault.example.com:8200
VAULT_ROLE_ID=<role-id-from-step-4>
VAULT_SECRET_ID=<secret-id-from-step-4>
EOF
sudo chmod 0600 /opt/event-capture/shared/vault-auth
sudo chown deploy:deploy /opt/event-capture/shared/vault-auth
```

## 7. Enable Vault Integration

Set the environment variable before deployment:

```bash
# On the VM, or in the Jenkins job environment
export EVENT_CAPTURE_VAULT_ENABLED=1
export EVENT_CAPTURE_VAULT_ENV=production
```

Or configure in Jenkins global properties.

## Usage

### Automatic (during deployment)

When `EVENT_CAPTURE_VAULT_ENABLED=1`, `deploy.sh` automatically fetches secrets
from Vault before starting services:

```
[deploy] vault integration enabled; refreshing secrets from Vault
[deploy] authenticating with Vault at https://vault.example.com:8200
[deploy] vault login successful
[deploy] fetching secrets for environment: production
[deploy] secrets written to /opt/event-capture/shared/production.env (47 lines)
```

### Manual refresh

After rotating a secret in Vault, refresh without a full deploy:

```bash
sh /opt/event-capture/current/deploy/vault-refresh.sh production

# Then restart affected services
cd /opt/event-capture/current
docker compose --env-file /opt/event-capture/shared/production.env \
               --env-file release.env \
               -f docker-compose.yml -f docker-compose.vm.yml \
               restart backend-api backend-worker
```

## Secret Rotation

### Rotating a single secret

1. Update in Vault:
   ```bash
   vault kv patch secret/event-capture/production/auth \
       turnstile_secret="new-secret-value"
   ```

2. Refresh on VM:
   ```bash
   ssh deploy@vm 'sh /opt/event-capture/current/deploy/vault-refresh.sh'
   ssh deploy@vm 'cd /opt/event-capture/current && docker compose ... restart backend-api'
   ```

### Rotating the share token keyring

The keyring supports multiple keys for zero-downtime rotation:

1. Generate a new key:
   ```bash
   NEW_KEY="prod-v2=$(openssl rand -base64 32)"
   ```

2. Add to Vault (keep the old key):
   ```bash
   vault kv patch secret/event-capture/production/auth \
       share_token_active_key_id="prod-v2" \
       share_token_keyring="prod-v1=<old-key>,prod-v2=<new-key>"
   ```

3. Deploy. New events encrypt with `prod-v2`; existing events decrypt with `prod-v1`.

4. After all old events are re-encrypted or expired, remove `prod-v1`:
   ```bash
   vault kv patch secret/event-capture/production/auth \
       share_token_keyring="prod-v2=<new-key>"
   ```

### Rotating the AppRole Secret ID

If the Secret ID is compromised:

1. Generate a new Secret ID:
   ```bash
   vault write -f -field=secret_id auth/approle/role/event-capture-deploy/secret-id
   ```

2. Update on VM:
   ```bash
   sudo sed -i "s/VAULT_SECRET_ID=.*/VAULT_SECRET_ID=<new-secret-id>/" \
       /opt/event-capture/shared/vault-auth
   ```

3. (Optional) Destroy the old accessor:
   ```bash
   vault write auth/approle/role/event-capture-deploy/secret-id-accessor/destroy \
       secret_id_accessor=<old-accessor>
   ```

## Environments

The secret path includes an environment segment:

```
secret/data/event-capture/production/...
secret/data/event-capture/staging/...
```

Set `EVENT_CAPTURE_VAULT_ENV` to switch environments:

```bash
EVENT_CAPTURE_VAULT_ENV=staging sh deploy/deploy.sh v1.2.3
```

## Troubleshooting

### "vault login failed"

- Check `VAULT_ADDR` is reachable from the VM
- Verify Role ID and Secret ID are correct
- Check the AppRole is enabled: `vault auth list`

### "missing X in vault"

The script validates required secrets exist. Check the path:

```bash
vault kv get secret/event-capture/production/auth
```

### Permission denied

Verify the policy is attached to the role:

```bash
vault read auth/approle/role/event-capture-deploy
# Should show: token_policies = [event-capture-deploy]
```

### Debugging

Enable verbose curl output by editing `vault.sh`:

```bash
# In vault_read(), change:
curl -fsS ...
# To:
curl -fsSv ...
```

## Fallback to Manual Secrets

If Vault is unavailable:

1. Set `EVENT_CAPTURE_VAULT_ENABLED=0`
2. Manually create/update `/opt/event-capture/shared/production.env`
3. Deploy normally

The format matches `env.example`.

## Audit Trail

Vault Enterprise and HCP Vault provide audit logs showing who accessed which
secrets when. For compliance, enable file or syslog audit:

```bash
vault audit enable file file_path=/var/log/vault/audit.log
```
